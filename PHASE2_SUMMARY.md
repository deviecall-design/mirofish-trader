Orchestrator Core (`src/orchestrator/orchestrator.ts`)\n\nThe foundation of the Swarm. It:\n- **Registers agents** — keeps a registry of all deployed agents (fundamental, technical, macro, sentiment)\n- **Dispatches signals** — receives investment signals and broadcasts to all agents in parallel\n- **Collects votes** — waits for agent analysis (with configurable timeout)\n- **Calculates conviction** — aggregates votes into a consensus decision with confidence score\n- **Emits events** — publishes signal, dispatch, and error events for downstream consumers\n- **Maintains state** — tracks active signals, voting queue, agent status, event log\n\n**Key Classes:**\n```typescript\nclass Orchestrator {\n  registerAgent(id, agent): void\n  async dispatch(signal): VotingResult\n  getState(): OrchestratorState\n  on(event, handler): void  // Event subscription\n}\n\nclass EventBus extends EventEmitter {\n  emit(event, ...args)\n  on(event, handler)\n  off(event, handler)\n}\n```\n\n### 2.   - Adapters and dashboard subscribe to events\n   - Loose coupling — phases can be deployed independently\n\n2. **Parallel Agent Analysis**\n   - All agents analyze simultaneously (not sequentially)\n   - Timeout protection (default 30s per agent)\n   - Graceful degradation: if 1 agent fails, others still vote\n\n3. **Conviction Scoring**\n   - Conviction = (% agents approved) × (avg agent confidence)\n   - Example: 3 agents, 2 approve (67%), avg confidence 0.8 → conviction = 0.53\n   - Dashboard uses conviction to visualize decision strength\n\n4. **Type Safety**\n   - Full TypeScript with strict mode\n   - Interfaces match across all phases (orchestrator → consensus → adapters → dashboard)\n   - No type gaps at integration points\n\n---\n\n## What Works Now\n\n✅
