## 1. What the app is

MiroFish Trader is a single-user **paper-trading dashboard**. It watches a list of symbols, writes a “signal” when a price has moved, and lets Damien approve or ignore that signal. Approving opens a simulated position (take-profit +5%, stop-loss −3%). Nothing here sends an order to a broker.

The pages on the live site are:

| Page | What it is for |
| --- | --- |
| Dashboard | Paper P&L, a “swarm consensus” dial, the top pending signal (“the swarm’s ask”), a queue, and a Jarvis chat box |
| Signals | History of signals, with Approve / Ignore on pending rows |
| Journal | Paper trades (entry, exit, percent P&L) |
| Performance | Win rate, average return, max drawdown, equity chart |
| Watchlist | Symbols the scanner is supposed to check, plus an “Add symbol” form |
| Screener | Sector lists with prices, charts, and a “Run swarm” button |

The header always says **Swarm 1000 agents**, **Execution paper**, and **Jarvis active**.

Under the hood, in the code that is actually in this GitHub repository, a scheduled job (`GET /api/cron/scan`, every 15 minutes) loads the watchlist from Supabase, fetches a price, and if the move is at least 2% it runs `runSwarm()` and inserts a row. Telegram can also approve or ignore with `/approve SYMBOL` and `/ignore SYMBOL`.

### 2.5 What looks real but is simulated, stale, or decorative

Say this plainly, because the screen is designed to look like a live trading desk.

1. **“1000 agents” is a label and a formula**, not a thousand models voting on each page load. In this repo the scanner does loop 1000 times, but each “agent” is `Math.random()` plus a sigmoid. Most stored signals (148 of 155) came out neutral.
2. **The agent ticker is generated from the last few signal rows** and a fixed phrase list. `AGENT-0447` is the placeholder before those rows load.
3. **“Jarvis active” does not mean Jarvis is healthy.** It is painted green in the header.
4. **The consensus dial is the top pending signal’s conviction, rescaled.** It is not a fresh vote. On review day that signal was four months old.
5. **The two May narratives are stored prose**, tagged `[MiroFish run_7d25cbf3]` (LYC.AX) and `[MiroFish run_8a6b41c1]` (DRO.AX). They read as forecasts (“will price LYC.AX as a late-stage breakout”, “DRO will gap up sharply”). They are not the scanner template, LYC.AX is not on the watchlist, and they are still `pending`, so the dashboard prefers them over everything newer.
6. **One BTC row says “Kronos projects … (heuristic)”.** Kronos is not in this repository. The sentence itself admits it is a heuristic. The UI still shows it as an ordinary signal.
7. **Total P&L (−53.30% on the dashboard) is the sum of each trade’s percent return**, not the return of one account. Performance says so in the subtitle (“cumulative percentage P&L”) and reports max drawdown **−154.92%**, win rate **47% (22 wins / 25 losses)**, average **−1.13%**, best/worst **+36.74% / −39.80%**. A drawdown past −100% is possible only because percents from different trades are added together.
8. **Prices are labelled as US dollars** (`formatUsd` in the journal and dashboard) even for ASX, LSE, and JSE symbols. IMP.JO around 19,516 is a rand price shown with a dollar sign.
9. **Screener prices are empty** because Yahoo is called from the browser. The API itself returns `"price": null`.
10. **Paper execution is labelled**, which is correct. The missing piece is a plain statement that this is not advice and that the swarm numbers are a score, not a headcount.

## 3. How Damien can update data

### What already works, today, without a developer

**A. Watchlist page — add only.** Type a ticker, pick a theme, press Add. That inserts a Supabase row. He cannot correct a typo, pause a symbol, or remove one from the website.

**B. Signals page — decisions, not wording.** Approve opens a paper trade at the current price. Ignore marks the row ignored. The written summary cannot be edited there.

**C. Telegram — same decisions, if the bot webhook is still set.** `/approve BTC` or `/ignore BTC` on the newest pending row for that symbol. This does not edit watchlist text or screener lists.

**D. Supabase Table Editor — this is the real day-to-day tool until an admin page exists.**

1. Sign in at https://supabase.com/dashboard and open the project whose URL contains `zmzvbppivxnyhcacxdxb`.
2. Open **Table Editor**.
3. `watchlist`: change `CENTRUS` to the real ticker, set `active` to false to pause a name, delete a bad row, or add a row. Theme can be any text; the website dropdown is only a suggestion.
4. `signals`: rewrite a `summary`, or set a stale pending row (the May LYC.AX and DRO.AX notes) to `ignored` so the dashboard stops featuring them.
5. `trades`: fix a bad paper trade, or set `status` to `closed` if a position should no longer show as open.

An agent acting for Damien does the same thing with the **service role key** (server-side only) or with Damien’s Supabase login. It should not use the anon key to write, and it should not put the service role key in the browser.

**What he cannot change without new code and a redeploy of the live source:** screener sector lists, the “1000 agents” label, Jarvis’s prompts, the 2% / +5% / −3% rules, page wording, and the disclaimer (there isn’t one). Market prices should keep coming from Binance and Yahoo. He should not type prices in by hand.

### Options for updating without editing code

#### Option A — Admin page on top of Supabase (recommended)

Add a password-protected `/admin` (or a Supabase login) that edits the tables he already has, plus new tables for the lists that are still hard-coded: screener sectors, themes, thresholds, the short disclaimer, and Jarvis’s starter prompts.

| | |
| --- | --- |
| Effort | **M** after the live source is back in git. The watchlist form is S. Screener + settings + auth together are M |
| Running cost | **$0 extra** on the Supabase project he already pays for (free tier is enough at this size). No new vendor |
| Security | Good **if** the admin password or Supabase Auth is required and the anon key loses write access. Dangerous if a new edit form is added on top of today’s open policies |
| Fit | Best. Trades, signals, and the watchlist already live here. Vercel cron already writes signals into the same database |

Day to day after this exists: Damien opens `/admin`, changes a ticker or a sentence, and refreshes the site. No git, no redeploy. An agent does the same through the admin form or a service-role script.

#### Option B — Google Sheet (or Airtable) as the list source

A private sheet with tabs `Watchlist` and `Screener`. A Vercel cron reads it with a server-side API key and upserts Supabase. Damien edits the sheet on his phone.

| | |
| --- | --- |
| Effort | **S–M**. Sheet plus one sync route. Awkward for trades and signal prose |
| Running cost | **$0** for a normal Google account. Airtable’s free tier is tight if the base grows |
| Security | The sheet must stay private. A public “anyone with the link” sheet would publish his list and, if mis-scoped, allow strangers to change what the scanner trades |
| Fit | Good for symbol lists. Poor as the only system, because journal and signals are already in Supabase. Two sources of truth |

Day to day: Damien edits the sheet; the site catches up on the next sync (for example every 15 minutes). An agent edits the same sheet through the Google API.

#### Option C — JSON or Markdown in GitHub, deployed by Vercel

Put screener lists, disclaimer, and Jarvis prompts in `content/*.json`. Merge to the deployed branch and Vercel rebuilds.

| | |
| --- | --- |
| Effort | **S** for an agent, once the real source is the repo Vercel builds |
| Running cost | **$0** |
| Security | Fine if the repo is private. A public repo would expose the content and the workflow |
| Fit | Poor for Damien himself (every change is a commit and a deploy, and a typo can break the build). Fine for an agent editing copy. Wrong tool for the watchlist he wants to change during the day |

### Recommendation

**Option A.** Use Supabase, which is already the system of record, and give Damien one admin screen. Use the Table Editor immediately so he is not blocked while that screen is built. Keep prices on the cron job. Do not add a CMS: this content is rows and numbers, not articles, and a second product would cost money without replacing Supabase.

Option B is the right fallback if he wants to edit lists from his phone before any code is written. Option C is how an agent should edit the disclaimer and Jarvis prompts only if they must ship before the admin page exists.

### Bigger

- **Auth and row-level security.** Policies in `schema.sql` allow the anon key to read and write every watchlist, signal, and trade for the fixed owner id. The site has no login. Anyone who loads the page can read the journal and can insert symbols, approve signals, and open paper trades, either through the buttons or by calling Supabase directly. Server actions `approveSignal`, `ignoreSignal`, and `addSymbol` do not check a user. `POST /api/jarvis` is called with no credential. `GET /api/debug/macro` is public. Telegram checks the chat id only when `TELEGRAM_CHAT_ID` is set, and does not check a webhook secret. Cron correctly returns 401 on the live site, but the code path with an empty `CRON_SECRET` allows the scan, and the secret is also accepted as `?secret=` which leaks into logs.
- **The scanner looks stopped.** No signal since 24 July 2026 despite a 15-minute cron in `vercel.json`. Check the Vercel cron log and whether the project plan actually runs `*/15 * * * *` (Hobby cron is daily). Also check Yahoo failures on the server.
- **P&L math.** Summing percent returns and calling the trough “max drawdown” produces −154.92%. Either show an equal-weight portfolio with a real equity curve, or rename the figure so it cannot be read as account loss.
- **Signal quality.** A 55% vote hurdle plus random jitter produces almost all “no clear edge” rows. The long-form run text is a different generator and is easy to mistake for research.
- **Tests and dependencies.** `app/lib/macroBias.test.ts` and `socialBias.test.ts` call Jest, but `package.json` has no `test` script and Jest is not installed. `npm audit` on 25 Sep 2026 reported a critical Next.js Server Components denial-of-service advisory (Next `16.2.4`) and high findings in `d3-color`, `nanoid`, `postcss`, `sharp`, and `ws`. No CI config is in the repo.
- **Homepage is prerendered** (`x-nextjs-prerender: 1`, Vercel cache HIT). The first paint is “INITIALISING SWARM” until the browser finishes reading Supabase. If that read throws, the spinner never clears (`setLoading(false)` is skipped in the `catch`).

### Australia (not legal advice)

Damien is in Australia. The Jarvis speech language is `en-AU`, and the clock uses `en-AU`.

The site is on the public internet with no login. It shows price targets, “the swarm leans short”, and sentences such as “will gap up sharply”. That can be read as financial-product advice. If this is only his private paper journal, the practical fix is to **put it behind a login** so it is not a public product. If other people can use it, he should speak to an adviser about an AFSL and the general-advice warning in the Corporations Act (section 949A): advice is general, it does not consider personal circumstances, and the person should consider appropriateness before acting.

Whatever the licensing answer, the page should say, in normal language, near the P&L:

- Paper trading only. No broker orders are sent.
- Not financial advice and not an offer to buy or sell.
- The “1000 agents” figure is a score, not a count of analysts.
- Past paper results are not a forecast.
- Prices may be delayed, in the wrong currency, or missing.

“Execution paper” in the header is not a substitute for that.
